# Workshop shop: a React client with Apollo Client 4

A React 19 page that lists the orders of the [shop server](../shop-server/README.md), with Apollo Client 4 and Vite. It replaces the old React 17 + apollo-boost client, which is kept for comparison in [`legacy/apollo-example/packages/client`](../../legacy/apollo-example/packages/client).

`src/OrderList.tsx` shows the open orders (`status: PLACED`) and works, but: one query for the whole page, hand-written types that nothing checks against the schema, and neither a loading nor an error state.

## Setup

```sh
npm install
npm test

# in a second terminal: the server on port 4000
cd ../shop-server && npm install && npm run start:solution   # Apollo Server 5 on Express 5

npm start            # http://localhost:5173, /graphql is proxied to port 4000
```

## Exercise 1: GraphQL Codegen with typescript-operations

1. `@graphql-codegen/cli` and `@graphql-codegen/typescript-operations` are already in `devDependencies`. Write `codegen.ts` (`codegen.solution.ts` shows the shape): schema `../shop-server/src/schema.graphql`, documents `src/**/*.tsx`, output `src/__generated__/graphql.ts` with the plugin `typescript-operations` and `nonOptionalTypename: true`.
2. Run `npm run codegen` and replace the hand-written `OrdersPageData` and `OrdersPageVariables` with the generated `OrdersPageQuery` and `OrdersPageQueryVariables` in `TypedDocumentNode<…>`. What type does `status` have now?
3. Rename a field in the query to something the schema does not have. What does `npm run codegen` say? Run codegen in CI, so the generated types never drift.

## Exercise 2: A fragment per row

1. Move the row into its own component `OrderRow` with `fragment OrderRow on Order { id status totalCents }` and read it with Apollo's `useFragment({ fragment, from: order })` from `@apollo/client/react`. The page only passes `__typename` and `id`.
2. Compose the fragment into the page query (`...OrderRow` plus `${ORDER_ROW}`): one request, no waterfall.
3. Render a loading state, an error state and an empty list, and test all three with `MockedProvider`.

## Solution

`solution/` contains a possible solution for both exercises (`solution/__generated__/graphql.ts` is generated by `npm run codegen:solution` from `codegen.solution.ts`): `npm run start:solution`.

Note: this recipe deliberately uses `typescript-operations` and Apollo's own `useFragment` instead of the client preset with its fragment masking – one way to read fragments, the one Apollo Client 4 brings along.
